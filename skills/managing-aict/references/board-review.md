# Board review requests

Loaded from `references/board-routing.md` when a submitted order carries a
`reviewRequest` — the student clicked *Review with X* on a plan version, the
master plan, or a results bundle. Handle it AFTER routing the ordinary
comments, so co-submitted manual comments are never lost.

   - **Review-request** (the fence has a `reviewRequest` — the student clicked *Review with X* on a plan version, the master plan, or a results bundle): handle it **after** routing the ordinary comments above, so any co-submitted manual comments are never lost. Then:
     - Do NOT delete or `--ack` the pending order yet — the reviewer run takes minutes and a crash mid-review must re-offer the request. Acknowledge (`python3 <script> --ack`) only after the reviewer finished and the board reopened with its seeds.
     - **Resolve the target from `reviewRequest.scope`** — it fixes the document to review, the review guidance, and the seed type:
       - **`plan`** → the execution-plan version (`component` / `version` / `planPath`); guidance = `${CLAUDE_PLUGIN_ROOT}/skills/managing-aict/references/plan-rubric.md`; comments anchor on the plan.
       - **`master`** → `plans/master-plan.md`; guidance = the research design (are the research questions answerable, is the component decomposition sound and independently completable, is the sequencing right); comments anchor on the Tracker.
       - **`results`** → the results bundle (`component` / `resultsVersion`) — its report and manifest; guidance = does the analysis support the stated findings, are the numbers and artifacts internally consistent, and what is missing; comments anchor on the Output & Validation surface.
     - Run the reviewer named by `agent` on that target. The **shared output contract** is identical across scopes — STRICT JSON `{"overall": "…", "comments": [{"section": "<exact heading or empty>", "quote": "<verbatim span — markdown stripped, no **, backticks, or []()>", "comment": "…"}]}`, quotes short and copy-paste so they match the RENDERED text of the target. Every comment's text begins with exactly one severity tag — `[blocker]` (invalidates a finding or decision — must be resolved before acting on the work), `[major]` (materially changes the work if acted on), `[minor]` (worth fixing, not blocking) — and comments are ordered most severe first; validate the tag on every returned comment and repair once (re-prompt) when it is absent or invalid. For `codex`/`gemini`, first **write the review prompt to a gitignored temp file** `plans/.aict-review-<slug>.txt` (fixed instructions + the target's content + its on-disk path(s) and the repository root + the scope's guidance + the contract; the fixed instructions carry the grounding and verify-before-returning rules — codex grounds claims in the repository read-only, while gemini is instructed to ground claims ONLY in the supplied material and to say so when it cannot support a judgment) — **never interpolate the target text into a shell command**, so content containing backticks or `$(…)` cannot be shell-expanded. Validate the returned JSON and repair or re-prompt once on malformed output. For `subagent`/`panel`, first run `python3 ${CLAUDE_PLUGIN_ROOT}/skills/managing-aict/scripts/models.py check` and relay its one-line hint verbatim if it prints one (advisory — proceed with the existing agents); if that hint reports the agents were renamed for the aict rename (restart needed), the `aict-board-reviewer` is not loaded yet this session, so spawn them anonymous below and note the pins reapply after a restart; otherwise when `.claude/agents/aict-board-reviewer.md` exists, dispatch each of these Task subagents by name (`subagent_type: "aict-board-reviewer"`) with NO model override — the agent file pins model and effort from `plans/model-profile.md`, a request the platform can override — otherwise spawn them anonymous as before. External reviewers (`codex`/`gemini`) are outside the profile: their models are pinned in their own CLIs. Before dispatching `codex`, run `command -v codex`; if it is missing, say "Codex is not available — pick another reviewer" and do not invoke it. Before dispatching `gemini`, run `command -v agy`; if it is missing, say "Gemini is not available — pick another reviewer" and do not invoke it. Dispatch on `agent`:
       - **`subagent`** — spawn a `Task` subagent with the target's on-disk path(s) and the repository root, the scope's guidance, and the contract (no shell, no injection surface). Pass the PATH, not the content: the agent has `Read, Grep, Glob` and opens the target itself, so inlining it duplicates the whole document in the prompt for nothing.
       - **`codex`** — `codex exec --sandbox read-only -m gpt-5.5 -o plans/.aict-review-out.txt "$(cat plans/.aict-review-<slug>.txt)" < /dev/null` — **read-only** (a review must not mutate the repo), the prompt passed via a shell-safe substitution, the final message saved with `-o`. Parse the LAST balanced JSON object from `plans/.aict-review-out.txt`.
       - **`gemini`** — `agy --model "Gemini 3.1 Pro (High)" --print-timeout 20m -p "$(cat plans/.aict-review-<slug>.txt)" < /dev/null > plans/.aict-review-out.txt 2>&1` — **without** `--dangerously-skip-permissions` (the prompt is self-contained, so the model needs no repo access or write). Parse the LAST balanced JSON object from `plans/.aict-review-out.txt`.
       - **`panel`** — spawn **three `Task` subagents in parallel**, each given the target's on-disk path(s) and the repository root + the scope's guidance + contract but a distinct lens (paths only, as above — three seats inlining one plan is three copies of it): **correctness** (does the work achieve its goal; internal consistency), **methodological rigor** (design, measurement, and inference validity), and **feasibility** (can this be executed or reproduced as written; scope, data, and time). Each seat already caps itself at 5 material comments. Collect all three JSON results and merge their `comments`: deduplicate first (same anchor AND substantively the same point — keep the copy with the highest justified severity), then **rank `[blocker]` > `[major]` > `[minor]`, by materiality within a tier, and keep the top ~5–7 across the whole panel** (each seat's own cap stays 5); two lenses flagging one span for *different* reasons may both survive if both are material. Each kept comment is stamped `author` = `"Subagent panel · <lens>"` so the student sees which lens raised it. If you drop comments to stay under the cap, say so in one line to the student (no silent truncation). Combine the three `overall` assessments into a single panel summary.
       A `codex`/`gemini` review runs for a few minutes — tell the student before launching, prefer background bash, and delete the temp prompt/output files afterward.
     - **Convert each comment to a seed for the target's scope** and write the array to a gitignored temp file (e.g. `plans/.aict-seed-<slug>.json`). Every seed carries `sectionHeading` (the comment's `section`), `quote`, `comment`, and `author` (the reviewer label — e.g. `Subagent`, `Codex`, `Gemini`, `Subagent panel · <lens>`); the routing fields differ by scope:
       - **`plan`** → `{"scope": "plan", "planPath", "component", "version", "isDraft", …}`
       - **`master`** → `{"scope": "master", …}` (no routing fields — it anchors container-wide on the Tracker)
       - **`results`** → `{"scope": "results", "component", "resultsVersion", …}`
     - Reopen the board on the target with the seeds and **relay the reviewer's `overall` assessment** (the combined summary for a panel) to the student — the anchored comments are seeded on the board; the top-level judgment is conveyed in the session so no part of the `{overall, comments}` contract is lost. Focus per scope (background/foreground exactly as step 4): `plan` → `--focus <component>`; `results` → `--focus <component>:r<resultsVersion>` (opens the bundle directly); `master` → no `--focus` (the Tracker is the default view) — e.g. `python3 ${CLAUDE_PLUGIN_ROOT}/skills/managing-aict/scripts/board.py [--focus …] --seed-annotations <file>`. The student curates the pending comments, drops any they disagree with, and presses **Send to Claude** — routing them back through this step 5 like their own feedback (each comment carries its `author`, so the decision-log entries attribute the reviewer, never the student). Delete the temp seed file afterward.
