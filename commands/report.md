description: Generate a shareable results-bundle report in Markdown, with PDF/DOCX via pandoc
argument-hint: <component name/number> [rN — default: latest bundle]
allowed-tools: Read, Write, Glob, Grep, AskUserQuestion, Bash(pandoc:*), Bash(python3:*), Bash(ls:*), Bash(date:*), Bash(mkdir:*), Bash(command:*)
---

Assemble a standalone, reader-readable report for one results bundle. Skill context: `${CLAUDE_PLUGIN_ROOT}/skills/managing-aict/SKILL.md`. Requires an initialized project (`plans/master-plan.md` with its marker); if absent, say so and stop. Reports are **derived documents**: they live in `plans/reports/` (committed, never gitignored), regenerating overwrites, and nothing about them is immutable — the immutable record is the bundle itself.

1. **Resolve the target.** `$ARGUMENTS` names a component (name or number via the master plan tracker) and optionally `rN`; default is the latest bundle. Read the bundle (`manifest.json`, `report.md`, `validation.md` if present), the governing plan version (`manifest.planVersion` → `plans/execution/<NN-slug>/v<N>.md`), the master plan (project name, the RQs this component serves), and the decision-log entries mentioning the component. If the bundle does not exist, say so and stop.

   **Null-result gate.** If the bundle has no substantive findings — no metric is `robust`/`marginal` and none carries a claim `statement`, so descriptive-only counts, retracted, and superseded metrics do not qualify — do **not** write a report. Say plainly that the bundle has no substantive findings to report, and stop without creating any file. The Output & Validation tab still carries the bundle's evidence and validation; the board's Report tab shows the null-result state. This gate holds identically for every entry path — a standalone `/aict:report`, the results-chained offer, and the board's Generate report button — so a null result never yields an empty narrative.

2. **Write `plans/reports/<NN-slug>-r<N>-report.md`** (`mkdir -p plans/reports` first), self-contained for a reader with no project context:
   - **Marker line (the file's very first line, exactly one line):** `<!-- aict-report {"schemaVersion": 2, "component": "<NN-slug>", "bundle": <N>, "plan": <N or null>, "validation": "<conforms|conforms-with-amendments|deviations-found|unverifiable|skipped|not-applicable|none>", "generated": "<YYYY-MM-DDTHH:MM>", "modelUsage": {"model": "<the model id you are running as>", "effort": null}} -->` — valid JSON on one line, closed with `-->`. The board parses this to flag stale reports and to show a "generated by" model chip. Use the bundle's current `manifest.validation.status`, or `none` when the bundle has no validation block.
   - **Header block:** project, component, plan v<N> — or **No governing plan** when `manifest.planVersion` is null (retrofit/adopted work), bundle r<N>, validation state (from `manifest.validation.status`, or none), generated date. One line each.
   - **1. Background and goal** — rewrite the plan's Goal and Context as prose (no template headers), naming the research question(s) served. For a planless bundle (`planVersion` null), the background comes from the master-plan tracker row and the bundle's capture note instead of plan Goal/Context.
   - **2. Data and methods** — from report.md's data-and-method note plus the producing scripts (name each script file and what it does in a phrase).
   - **3. Findings** — each manifest metric: the `statement` as a lead sentence, then `label`, `value`, `note`, `status`, then **that finding's figures and tables embedded directly beneath it** (the artifacts its `artifactIds` names): `![<title>](../execution/<NN-slug>/results/r<N>/artifacts/<file>)` with the caption on the next line — paths RELATIVE to `plans/reports/` so the markdown renders on GitHub and in editors. Tables embed their `.png` render; note `.tex` availability in the caption line when present. Artifacts no finding references follow in an **Additional evidence** section after the last finding. When no metric has `artifactIds`, keep a single standalone **Figures and tables** section instead (the pre-reports-tab layout).
   - **4. Validation summary** — two parts, so a reader sees every check. **Integrity:** the `manifest.integrity` status (`passed`/`failed`) with its four checks (checksums, artifacts-present, artifact-refs, findings-sourced) — a `failed` integrity (e.g. an unsourced finding) must be shown, not hidden; "not recorded" when the block is absent (a pre-integrity bundle). **Plan conformance:** the `manifest.validation` status plus its steps/criteria as a compact table; "not validated" when absent.
   - **5. Provenance appendix** — scripts with repo paths and sha256s from the manifest, source-drift state (`python3 ${CLAUDE_PLUGIN_ROOT}/skills/managing-aict/scripts/results.py changed --component <NN-slug>`), and the related decision-log entries (timestamps plus a one-line gist).
   - **6. AI Assistance Disclosure** — reuse the `modelUsage: {model, effort}` data already captured at each stage; do not invent a new tracking mechanism, just render what already exists. Build a two-column table (stage | model), one row per stage that ran for this component/bundle, each model cell `<model>` or `<model> (effort: <level>)`:
     - **plan** — from the governing plan version's first-line `<!-- aict-model ... -->` marker (`plans/execution/<NN-slug>/v<N>.md`).
     - **plan review** — from `plans/reviews/<NN-slug>-v<N>.md`'s `modelUsage` field, when that scorecard exists.
     - **execute** — from this bundle's `manifest.modelUsage`.
     - **results validation** — from `manifest.validation.modelUsage`, when the bundle was plan-conformance validated.
     - **report** (this document) — the model generating this report right now.
     Omit a row entirely when its source has no `modelUsage` field at all (never write a row of all dashes). After the table, add one sentence pointing the reader to the verifiable record: "This table is derived from provenance markers on the plan, scorecard, and results bundle; `plans/decision-log.md` and the results bundle at `plans/execution/<NN-slug>/results/r<N>/` are the underlying verifiable record — including any `decision-log.md` entries flagging AI-drafted interpretive text the student has not yet revised in their own words (see CLAUDE.md rule 11)."

   No overclaiming: every number traces to a metric or artifact; the report never introduces findings the bundle does not contain.

3. **Convert.** Check `command -v pandoc`. When available, run from `plans/reports/` so the relative image paths resolve: `pandoc <name>.md -o <name>.pdf` (needs a LaTeX engine; on failure report which is missing) and `pandoc <name>.md -o <name>.docx`. Markdown is always the source of truth; report honestly which conversions succeeded and why any failed (pandoc missing, no LaTeX engine) — never fabricate success.

4. **Wrap up.** List the written files with sizes. Suggest a commit such as `plans: report — <NN-slug> r<N>` (do not run without approval). Reopening belongs to the caller: when this run was chained from `/aict:results`, just return — likewise when chained from the execution loop: write the files and return; no commit suggestion, no board offer (the loop owns both). When triggered from the board's Generate report button, relaunch per `/aict:board` (it refocuses with `--focus <NN-slug>:r<N>:reports`). Only a standalone `/report` run offers to open the board (`/aict:board <NN-slug>:r<N>:reports`).
